# بَيِّن | BAYYIN

**تحقّق قبل أن تنشر.**

مساحة عمل للتحقق من المحتوى ومصادره قبل النشر (Content Verification Workspace).
يقسّم النص إلى ادعاءات قابلة للتحقق، ويعرض لكل ادعاء حالته ومصدره وسبب تصنيفه.

> **بَيِّن ليس Chatbot.** لا محادثة، ولا توليد نصوص. هو بوابة جودة قبل النشر.

## ⚠️ ما يعمل فعليًا وما لا يعمل — اقرأ هذا أولًا

| المكوّن | الحالة |
|---|---|
| تقسيم النص إلى ادعاءات | ✅ **يعمل فعليًا** — تجزئة لغوية حتمية محلية، بلا نموذج وبلا اتصال |
| قاعدة الإحالة لمختص | ✅ **تعمل فعليًا** — قرائن لفظية صريحة في `verify/engine.ts` |
| احتساب الملخص والجاهزية | ✅ **يعمل فعليًا** |
| سجل العمليات | ✅ **يعمل فعليًا** — محفوظ في `localStorage` على الجهاز |
| **ربط المصادر المعتمدة** | ❌ **غير موجود** — المزوّد الافتراضي لا يعيد أي نتيجة |
| **مراجعة سياقية بالذكاء الاصطناعي** | ✅ **اختيارية، مطفأة افتراضيًا** — تنبيهات فقط بعد النتيجة الحتمية (انظر القسم أدناه). تحتاج `ANTHROPIC_API_KEY` على الخادم |

**نتيجة مباشرة:** ما دامت المصادر غير مرتبطة، **لا يمكن لأي ادعاء أن يظهر بحالة «موثّق»**
في المسار الحقيقي. هذا سلوك مقصود لا نقص في التنفيذ، والواجهة تعلنه صراحةً في الصفحة
الرئيسية وفي صفحة النتيجة.

## المراجعة السياقية بالذكاء الاصطناعي

طبقة مستقلة تأتي **بعد** نتيجة التحقق الحتمية، ولا تملك أي مسار لتغييرها.

```
النص ← تقسيم ← مطابقة ← حالة ← جاهزية      (حتمي، يُعرض فورًا)
                         │
                         ▼  فقط إذا فعّل المستخدم المفتاح
        POST /api/context-review ← النموذج ← تحقق الخادم من المخرجات
                         │
                         ▼
        قسم مستقل في البطاقة: «مراجعة سياقية بالذكاء الاصطناعي»
```

| يفعله الذكاء الاصطناعي | لا يفعله |
|---|---|
| يقرأ مقاطع المستخدم ويختار إشارة من قائمة مغلقة | لا يتحقق من نص القرآن ولا من حديث |
| يقتبس دليله حرفيًا من نص المستخدم | لا يذكر سورة أو آية أو حديثًا أو مرجعًا |
| ينبّه إلى مراجعة المقطع مع مختص | لا يغيّر الحالة ولا الجاهزية ولا المصادر، ولا يمنح «موثّق» |
| | لا يفسّر ولا يفتي ولا يصحح نصًا، ولا يُعرض له نص حر |

- **النموذج:** `claude-opus-5-5` عبر `@anthropic-ai/sdk`، بمخرجات مقيّدة بمخطط (Structured Outputs + Zod).
- **الإشارات:** `interpretive_inference` · `personal_religious_question` · `possible_hadith_attribution` · `context_requires_specialist` · `none`.
- **تحقق الخادم:** يُسقط كل تنبيه دليله غير موجود **حرفيًا** في نص المقطع (`lib/ai/validate.ts`).
- **النص المعروض:** عنوان كل تنبيه وشرحه ثابتان في `lib/ai/signals.ts`؛ لا يُعرض شيء كتبه النموذج.
- **ما يُرسل:** نص المقاطع غير «الموثّقة» وأرقامها فقط. لا السجل، ولا نتائج المطابقة، ولا أي معرّف.
- **عند التعذر** (لا مفتاح، مهلة، خطأ مزوّد، مخرجات غير صالحة): تظهر «المراجعة السياقية غير متاحة حاليًا» وتبقى النتيجة كما هي.
- **السجلات:** الخادم يسجّل سبب التعذر ومدته فقط، لا النص ولا المخرجات.
- **التشغيل:** ضع `ANTHROPIC_API_KEY` في `.env.local` (انظر `.env.example`). المفتاح يبقى على الخادم.

### لا مصادر شرعية إطلاقًا

المشروع **لا يتضمن أي مصدر شرعي: لا حقيقيًا ولا مُفترضًا ولا مُفبركًا.**

المثال التوضيحي في `lib/data/demo-case.ts` يستخدم نصًا محايدًا عن مراجعة النشر،
وسجلاته اسمها الحرفي «سجل تجريبي ١» ضمن «مجموعة سجلات تجريبية — ليست مصادر»،
وكل سجل موسوم `isDemo: true` ويظهر في الواجهة بشارة **«سجل تجريبي — ليس مرجعًا»**.

### الفصل بين طبقة المصادر ومنطق التحقق

هذا الفصل مقصود وصريح:

- **`sources/provider.ts`** يعرّف `SourceProvider` فقط. لا يعرف شيئًا عن التصنيف.
- **`verify/engine.ts`** يستقبل `SourceMatch[]` ويقرر الحالة بناءً على **درجات الترشيح**
  فقط. لا يصل إلى أي مرجع، ولا يعرف هوية المصادر ولا مضمونها.

تغيير المزوّد لا يمس المحرك، والعكس صحيح.

## ربط مصادر معتمدة لاحقًا (RAG أو فهرس أو API)

1. نفّذ الواجهة في ملف جديد داخل `lib/sources/`:

```ts
import type { SourceProvider } from "@/lib/sources/provider";

export const myProvider: SourceProvider = {
  name: "اسم مزوّد المصادر",
  connected: true,
  async lookup(claim) {
    // ابحث عن مواضع استدلال لنص claim.text
    // وأعد SourceMatch[] بدرجات confidence من 0 إلى 1
    return [];
  },
};
```

2. سجّله عند إقلاع التطبيق:

```ts
import { setSourceProvider } from "@/lib/sources/provider";
setSourceProvider(myProvider);
```

**لا يلزم تعديل أي ملف في `verify/` ولا في الواجهة.** بمجرد أن يصبح
`connected: true` وتعيد `lookup` نتائج، ستبدأ حالة «موثّق» بالظهور تلقائيًا.

### عتبات التصنيف

في `verify/engine.ts`:

- `confidence ≥ 0.82` → **موثّق**
- `confidence ≥ 0.45` → **يحتاج تحقق**
- ما دون ذلك أو لا نتائج → **غير مسند**
- قرينة حكم أو ترجيح في النص → **إحالة لمختص** (تسبق كل ما سبق)

## ملاحظات تقنية

- Next.js 16 · React 19 · TypeScript · Tailwind CSS v4
- واجهة أمامية فقط — لا قاعدة بيانات، لا مصادقة، لا خدمات خارجية
- الحالة في `localStorage` عبر `useSyncExternalStore`
- `robots: noindex, nofollow` — النموذج غير مُعدّ للفهرسة
- التنبيه بأن **بَيِّن أداة مساعدة وليس بديلًا عن المختص** ظاهر في الصفحتين
